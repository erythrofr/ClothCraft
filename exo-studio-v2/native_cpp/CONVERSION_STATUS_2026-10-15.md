## Critical implementation limitations

1. The buildSimulation native adapter accepts a premeshed JSON particle/face/constraint snapshot. A *separate* native authored-pattern mesh adapter now matches the tested tee (768/768 triangle indices, 38/38 cutline boundary index lists) and pants (320/320 triangles, 28/28 lists), plus midpoint subdivision, with approximately 1e-16 m initial-placement differences. These **do not yet form one fully integrated solver**: paired sewing/virtual constraint generation, unusual contours/Earcut fallback, all wrap modes, collision response and arbitrary garment patterns remain unverified. StepSimulation matches a limited real tee step with collisions/wind disabled, not the general solver.
2. Self collision, nearest triangle avatar mesh contact, seam assembly and staged drape transfer have independent native primitives/adapters. They do not imply one integrated collision-checked continuous garment solve; they cannot operate directly on live JS THREE objects and some require caller-injected body-clearance callbacks.
3. PPF remains the original Rust solver, with an independently guarded C++/HTTP bridge and prepared payload snapshots. No passing end-to-end clothed-avatar fit, continuous collision detection certification, or sign-off for production has been established.
   Experimental native seam preassembly has a C++ static avatar-clearance proxy on sampled positions, not swept collision handling, and the assembly result is never marked safe to auto-apply.
4. The native Qt GUI can edit basic drafting patterns, grade sizes, inspect construction, and export development production data. Advanced 2D tooling, renderer, simulation playback and full feature parity remain unfinished. The Simulate action remains intentionally disabled until a physically valid case passes its gates.
5. SDK packaging and macOS codesigning, extensive UI interaction tests and supplier/factory-approved output verification remain open.

## Reproduce the status

From the repository root:

    node scripts/check-native-cpp-conversion-coverage.mjs --run-parity
    python3 -m cmake -S native_cpp -B native_cpp/build-cmake -DGARMENT_BUILD_QT=OFF
    python3 -m cmake --build native_cpp/build-cmake -j4
    python3 -c 'import cmake,subprocess,os;raise SystemExit(subprocess.call([os.path.join(cmake.CMAKE_BIN_DIR,"ctest"),"--test-dir","native_cpp/build-cmake","--output-on-failure"]))'

Qt example (using this machine's isolated SDK):

    python3 -m cmake -S native_cpp -B native_cpp/build-qt-current -DCMAKE_PREFIX_PATH="$PWD/native_cpp/.qt-sdk-worker1/6.8.3/macos" -DGARMENT_BUILD_QT=ON -DGARMENT_REQUIRE_QT=ON
    python3 -m cmake --build native_cpp/build-qt-current --target GarmentStudioQt -j4

Do not infer total application completion from the export-mapping ratio, and rerun the audit rather than reusing the recorded values when new modules are integrated.
