# EXO Sample 3D — evidence-based project history

**Recorded through 15 October 2026.** This chronology is based on the local Git commit log and explicitly dated repository research reports. The application has previously used **Garment Studio** and **SAMPL3D** naming; the current product name is **EXO Sample 3D**. The primary agent reports that the GitHub repository has now been renamed to `mikristian/exo-sample-3d` and the package renamed to `exo-sample-3d`; public release remains pending. The former `mikristian/SAMPL3D` repository identity belongs to the same project's history. A dated research report shows that work had been investigated by that date; it does not necessarily establish the exact date a source line was introduced, merged or shipped.

## How to interpret the record

There are three evidence types in this history. **Git commits** provide an exact recorded commit date, revision hash and subject. **Dated engineering reports** document observations, experiments, test evidence and limitations at the time of their writing. **Current README, status and roadmap documentation** describe a desired product direction, occasionally revising previous architectural assumptions. They are not proof that a milestone was shipped. All cited reports are local files; their titles and timestamps are part of the preserved audit trail. This chronology does not infer development dates from the date a screenshot file was generated, a document was rewritten or a remote repository was made visible.

## Recorded precursor: September 25

The two September 25 commits support a limited origin statement. An open development baseline existed under Garment Studio branding, and a live native XPBD backend plus Blender handoff were added in recorded Git history. This does not justify assigning September 25 as the invention date of pattern drafting, fabrics, the UI or any broader product concept. For architecture background, see [architecture](ARCHITECTURE.md) and [native simulation audit](ARCHITECTURE_AUDIT_CLOTH_SIMULATION_2026-10-13.md).

The later system uses several cooperating implementations. A web-based React and Three.js garment editor provides a rich interface. Native C++ routines support drafting, geometry and production transformations as migration proceeds. Rust PPF is an optional separately configured numerical solver, originally integrated through a local service and Blender scene preparation. There is also a macOS wrapper and native Qt desktop work. These parts progressed at different rates; describing all of them as a single, completed C++ rewrite would obscure the boundaries developers need for reproducibility.

## October 13 — public-source hygiene and initial release gates

October 13 has the clearest source preparation record: the `50a3be5` commit adds a sanitized GPL-3.0-only source baseline, and `e8826c1` adds public-source validation and native macOS CI. The [open-source readiness audit](OPEN_SOURCE_RELEASE_READINESS_AUDIT_2026-10-13.md) explicitly says **not ready to publish** when written. Its risks included a locally present CLO-derived Thomas avatar, unreviewed source history, missing rights verification for third-party content, upstream PPF runtime distribution terms and insufficient release evidence.

The decision to use GPL-3.0-only for the main source is documented; it never automatically conferred rights over every model, texture, music track, font or upstream dependency. The audit called for removing restricted assets from public packages, reviewing Git history and checking bundled licenses. It also explained that a MakeHuman-derived model could be considered only after confirming provenance and accompanying license notices. Later gallery work indeed used a neutral MakeHuman-derived fitting avatar, but the public source checklist still called for a complete history scan and release-specific rights verification. See [licensing](LICENSING.md), [candidate validation](OPEN_SOURCE_CANDIDATE_VALIDATION_2026-10-13.md), and [release status](EXO_RELEASE_STATUS.md).

October 13 simulation reports describe active work on physically sewn panels, avatar fitting and cloth constraints. [First tee fit test](FIRST_TEE_FIT_TEST_2026-10-13.md), [sew-first nonrigid assembly](SEW_FIRST_NONRIGID_ASSEMBLY_2026-10-13.md), [progressive torso/shoulder assembly](PPF_PROGRESSIVE_TORSO_AND_SHOULDER_ASSEMBLY_2026-10-13.md) and [PPF physical sewing](PPF_PHYSICAL_SEWING_IMPLEMENTATION_2026-10-13.md) are dated investigative milestones, not proof that all tee trajectories worked. The solver had to deal with sleeve alignment, stretched seams, staged starting positions, pins, high strain and body intersection. A final image of fabric touching an avatar was insufficient evidence of an acceptable physical state.

The same date also saw deep interface and product comparisons. Reports such as [CLO viewport overhaul](CLO_VIEWPORT_UI_OVERHAUL_2026-10-13.md), [CLO tool icon audit](CLO_TOOL_ICON_AUDIT_2026-10-13.md) and [non-simulation CLO audit](CLO3D_NON_SIMULATION_FULL_BUILD_AUDIT_2026-10-13.md) catalogued differences in workspace ergonomics and production features. These investigations establish an intent to approach selected CLO3D-like workflows, but do not constitute an independent complete-feature parity evaluation. The [CLO simulation gap audit](CLO3D_CLOTHING_SIMULATION_GAP_AUDIT_2026-10-13.md) remains an essential statement of the hardest unresolved requirements.

Material and geometry validation were also being examined. [Native mesh quality](NATIVE_MESH_QUALITY_PASS_2026-10-13.md), [native first-frame assembly](NATIVE_FIRST_FRAME_ASSEMBLY_AUDIT_2026-10-13.md) and [contact/strain review](JARVIS_CONTACT_STRAIN_REVIEW_2026-10-13.md) show that clean triangulation, correct panel orientation and readable stress diagnostics were being treated as independent work. A good first-frame mesh is necessary for sewing and simulation, but cannot demonstrate CCD or real garment fit.

## October 13 — Rust PPF experiments and failure preservation

The most instructive historical artifact is a Rust PPF Metal fitting trajectory evaluated in the [October 14 deep audit](PPF_ACTUAL_GARMENT_FIT_DEEP_AUDIT_2026-10-14.md) from an October 13 fixture. Native solver execution completed: a 20-frame animation with 500 cloth vertices, 768 faces and 98 stitch pairs was produced. The measurement confirmed substantial reduction in average stitch separation, and PC2 export faithfully matched native coordinates. That correctness of export is significant, because it eliminates animation conversion as an explanation for later body crossings.

Nevertheless, the fitting result **failed**: the largest remaining stitch gap was 9.979 cm, avatar triangle intersections began at frame 3, the report observed up to 192 intersecting avatar triangle pairs, swept CCD failed entering frame 3, and shoulder/torso clearances exceeded acceptance limits. The report explicitly attributed these errors to the native solver trajectory rather than a rendering illusion. This is the appropriate project precedent: a real solver run can be both technically successful as execution and unacceptable as apparel fitting.

The deep audit also recorded a separate improved tee preassembly whose maximum stitch-start gap was 19.291 cm, above a guarded 3 cm launch threshold. It was not an accepted production PPF solve. Keeping those two failures distinct prevents a false narrative that later initialization research resolved the original contact problem. Additional dated investigations include [contact gap experiment](PPF_CONTACT_GAP_2MM_EXPERIMENT_2026-10-13.md), [contact safety](PPF_CONTACT_SAFETY_NEXT_PASS_2026-10-13.md), [IPC swept contact](IPC_THOMAS_SWEPT_CONTACT_INTEGRATION_2026-10-13.md) and [strain finding](PPF_RAW_EXPORT_STRAIN_FINDING_2026-10-13.md).

## October 14 — deeper pattern and body-fitting analysis

The October 14 reports document focused attempts to transform feature development into reproducible fit evaluation. [Exact T-shirt pattern import and sewing map](CLO_MALE_TSHIRT_TRUE_PATTERN_IMPORT_AND_SEWING_MAP_2026-10-14.md) and [male tee DXF import](CLO_MALE_TSHIRT_DXF_IMPORT_2026-10-14.md) examine source pattern fidelity and seam mapping. [2D reference layout diff](CLO_2D_REFERENCE_LAYOUT_DIFF_2026-10-14.md) and [nonblocking drafting](2D_NONBLOCKING_DRAFTING_PASS_2026-10-14.md) address usability and visual interaction as the authored pattern becomes more complex.

On the physics side, [PPF actual fit deep audit](PPF_ACTUAL_GARMENT_FIT_DEEP_AUDIT_2026-10-14.md), [interpolation diagnosis](PPF_EXPORTED_FRAME_INTERPOLATION_DIAGNOSIS_2026-10-14.md), [body-relative assembly](CLO_BODY_RELATIVE_PPF_ASSEMBLY_EXPERIMENT_2026-10-14.md) and [upstream pin-motion forensics](PPF_UPSTREAM_PIN_MOTION_FORENSICS_2026-10-14.md) were concerned with issues beyond static appearance. They examined the difference between authoring a panel, placing it around a body, actually solving a motion sequence and exporting that sequence. This sequence matters: it is possible for a garment to display in a plausible resting pose while still producing catastrophic crossings after a pose change.

An engineering handoff document, [C++/Rust PPF worker handoff](JARVIS_WORKER_HANDOFF_CPP_RUST_PPF_2026-10-14.md), emphasizes complementary responsibilities rather than one language displacing all others. C++ is suitable for precise CAD, native UI modules, conversions and tested adapters; the Rust PPF solver can continue to own its numerical runtime while dedicated source parity and physical acceptance checks evaluate integration. The [native Qt rewrite plan](NATIVE_CPP_QT_REWRITE_PLAN_2026-10-14.md) describes a transition strategy, not an assertion that the finished standalone UI already existed on October 14.

The October 14 documentation also records efforts to make physical simulations repeatable on Apple Silicon. [Metal repeatability results](PPF_METAL_REPEATABILITY_AND_SMOOTH180_RESULTS_2026-10-14.md) and [PPF backend integration checkpoint](NATIVE_PPF_INTEGRATION_CHECKPOINT_2026-10-14.md) should be consulted before interpreting a newly passing frame count. A reproducible solver result is only the beginning; repeated results can still be wrong in the same way.

## October 15 — native C++ expansion and Qt desktop proof

The October 15 [native conversion checkpoint](SAMPL3D_NATIVE_CPP_CONVERSION_LOOP_2026-10-15.md) documented C++ module expansion covering construction DXF, native pattern meshing and flat OBJ interchange, with parity checks for real garment fixtures. The report identified a clear distinction between correct flat rest geometry and sewn simulated fit. A construction DXF being byte- or entity-compatible with a JavaScript reference does not establish industrial AAMA/ASTM acceptance.

The dated [native Qt desktop build report](SAMPL3D_NATIVE_QT_DESKTOP_BUILT_2026-10-15.md) establishes an important progression after an earlier SDK blocker: an appropriately configured Qt 6.8.3 arm64 SDK was obtained, `GarmentStudioQt.app` compiled and launched in an isolated offscreen smoke test. The report recorded a visible window, four sample pieces, a native 2D drafting canvas, curved outlines, fabric markers and export actions. This is concrete runtime evidence of a native Qt application. It does not mean the installed web-based workspace was replaced or that full 3D drape functionality had been validated in Qt.

The project simultaneously pursued native parity for garment topology, stitching, material maps, avatars and factory output. Supporting October 15 audits include [native grading/cutting](NATIVE_CPP_GRADING_AND_CUTTING_PASS_2026-10-15.md), [POM parity](NATIVE_CPP_POM_PARITY_2026-10-15.md), [BOM and markers](NATIVE_CPP_BOM_AND_MARKER_PARITY_2026-10-15.md), [fabric parity](SAMPL3D_FABRIC_PARITY_AUDIT_2026-10-15.md) and [ClothCraft C++/Rust interchange](CLOTHCRAFT_CPP_RUST_INTEROP_2026-10-15.md). Each audit covers a bounded scope. Some conversion work can pass a subset of fixtures while untested variants, full engine integration and physically meaningful behavior remain open.

## October 15 — production export and external acceptance

The [production comparison](CLO_EXPORT_PRODUCTION_PARITY_2026-10-15.md) describes functioning DXF, graded factory packaging, structural preflight, BOM XML, POM tables, fabric-specific marker output, PDF/SVG plotting and consumption/costing paths. It records tests of true-scale PDF dimensions, download behavior and output packaging, along with a more complete ZIP for a hoodie fixture. These are meaningful manufacturing workflow components.

That audit is unusually explicit about what remains: no verified AAMA/ASTM industrial importer compatibility, incomplete industrial grade-rule interchange, no verified HP-GL cutter stream, limited contour-aware nesting and manual marker controls, incomplete CLO-specific BOM interchange, and no confirmed physical factory cut. A screenshot of an export dialog cannot establish those outcomes. The report rejects an unsupported **90% CLO3D parity** claim and says a historical selected-feature audit on another scope must not be reused as an updated whole-product percentage. See [production pipeline](EXO_PRODUCTION_PIPELINE.md) and [validation test plan](EXO_VALIDATION_TEST_PLAN.md).

## What this history establishes, and what it does not

The verified trajectory is toward a multi-component apparel CAD and simulation application with real 2D authoring, multiple independent geometry/export tests, ongoing C++ migration, an optional Rust solver, an initial Qt desktop smoke test, and substantially improved public-source documentation and media. This history is not a completion certificate. The authoritative unresolved areas include robust multi-frame body and self-collision, calibrated fabric mechanics, multi-size physical garment fit, industrial CAD interoperability, actual cutting verification, broader packaged-desktop parity and long-term release hygiene.

Future entries should cite a Git hash or a dated immutable test artifact, identify both a pass and the limits of that pass, and maintain separate records for source implemented, tests executed, external pilot verified and production approved. Where a milestone cannot be dated without speculation, describe it as a current or historical capability without assigning a fabricated day. The companion [milestone issue board](EXO_MILESTONE_ISSUE_BOARD.md) turns these specific gaps into scoped, independently closable work.
