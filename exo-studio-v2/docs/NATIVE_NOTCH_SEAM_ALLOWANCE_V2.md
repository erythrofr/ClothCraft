# Native notch and seam allowance authoring, V2

The source Rust `authoring::apply` accepts `Command::Notch { panel, edge, t, depth_m }`, `Command::RemoveNotch { panel, edge, t }`, and `Command::SeamAllowance { panel, edge, width_m }`. `t` is a strictly interior fraction of a named contour edge's sampled material arclength. All metric values are in metres. Notch depth must be finite and positive. Seam allowance widths are finite in the range 0 to 0.5 m; zero removes the allowance. Notches at positions within 1e-9 of an existing notch replace its depth. Removal uses that same tolerance.

`PolygonPattern.notches` and `PolygonPattern.seam_allowances` are optional serde-default maps keyed by stable contour edge IDs. `EdgeNotch` stores `{ t, depth_m }`. `PolygonPattern::notch_segment` returns the notch foot and outward tip in material UV coordinates, tracing curved edges through the same flattened samples used by boundary authoring. `PolygonPattern::allowance_guide` returns a separate outward offset polyline for one boundary using vertex tangents. The material polygon, rest mesh, physics, and stitches remain unchanged. These are 2D drafting markings and independent cutting guides; there is **no** assembled seam allowance polygon, corner joining, self-intersection repair, cutter export, or physical fabric extrusion. Do not represent the guide as production-ready cutting geometry.

The edited template is compiled before acceptance, and the existing `History::record` / `restore` snapshots provide undo and redo when the caller records a successful edit. `same_physics` omits both annotation maps when deciding whether to reset simulation. Splitting or removing a boundary with authored notches or allowances is rejected to avoid silently orphaning marks. Existing documents deserialize with empty maps.

The native request adapter must explicitly map those three variants to `Command` and save their returned template. UI tools should display the notch line and allowance guide using material UV coordinates. Tests cover outward orientation, width and position, serialization, and unchanged contour coordinates.
