## Classification and proposed priority

## Delivery order and test gates

1. **First 2D authoring sprint:** implement Trace, Walk Pattern, and stable native graphic assets/UV transforms. Prefer the existing editor UX, but give graphic records Rust identity before treating them as save/export-capable. Add print image regression tests (SVG, transparent PNG, large/invalid payload) and verify patterned white 2D panels remain unchanged.
2. **Second 2D production sprint:** Topstitch, annotations, fullness and pleats; then grading and layer/material fill. Use an explicit topology version and remap dependent seam, notch, trim and graphic anchors whenever points/edges change. Never call an Object Browser category click proof of native authoring.
3. **3D dependency sprint:** 3D graphics manipulation and editable stylelines/strokes on the same 2D pattern coordinates; then buttons, zippers and trim. Require native constraint tests and hardware geometry fidelity before enabling each corresponding reference icon.
4. **Physics and specialized sprint:** steam, seam taping, puckering, folds, remeshing, avatar measurement/motion and press only after solver signatures, repeatability metrics and golden snapshots exist.

**Universal enablement gate for each position:** one committed Rust operation changes the intended data structure; Undo and Redo roundtrip its exact typed record; Save and fresh process Reopen preserve IDs/geometry/material relationships; rendering follows native snapshot state; malformed input fails without revision changes; no unrelated panel or 2D drafting fill changes. For purely observational workflows, define a read-only verification instead. Update the capability registry from `unavailable` only after these checks pass. Fabric inspector property sliders must map to real material properties (not texture-only display), and garment graphic browser-side IndexedDB persistence must remain clearly labeled until native document/export support exists. Photo-reference tool names marked uncertain in the CLO reference must be corroborated with actual CLO7 tooltips before claiming exact feature parity.
