# EXO ClothCraft V2 — CLO3D 7.0 Property Editor parity program

**Date:** 2026-10-16. **Scope:** V2's right-hand Property Editor under Object Browser, covering native ClothCraft 2D/3D garment selection and the EXO draft document. **CLO reference:** installed `/Applications/CLO_Standalone_OnlineAuth.app`, version 7.0.242, confirmed running. **Evidence limitation:** macOS denied `osascript` Assistive Access (`-25211`, UI elements enabled = false); `screencapture` could not create an image of the display. Thus no claim of visually inspecting or exactly replicating every locally installed CLO dropdown is justified. All official-source control names and local/version uncertainty are recorded in `docs/CLO3D_PROPERTY_EDITOR_DEEP_AUDIT_20261016.md` (selection matrix and 15 executable acceptance scenarios). This document is the implementation status and integration plan, not a CLO GUI screenshot transcript.

## What was implemented in this cycle

1. **Typed property edit and real selections.** `src/core/cloPropertyCommands.js` contains explicit allowlists, type/range checks and exact object resolution for `pattern`, `fabric`, `button`, `buttonhole`, `topstitch`, and `graphic` EXO draft entities. No unknown property, missing ID, wrong type, invalid fabric reference, out-of-range field or malformed color is allowed to change the project. Changes pass through App's existing `mutateProject` for Undo/Redo, rendering and local saved document. Browser row selection carries `pieceId` and `itemId` (not a label-derived guess), including identical names in different pattern pieces. The edit boundary is intentionally not exposed as a network agent action without further revision and authorization validation.
2. **Context-sensitive accordions.** `src/components/CloPropertyEditorAccordion.jsx` keeps existing stable all-eight pattern groups plus the long-lived PatternEditor precision-controls portal. Fabric assets reveal Information, Simulation Properties, Fabric, Miscellaneous. Selecting individual buttons, buttonholes, graphics or topstitch instances reveals their distinct property categories and only the object-compatible field controls. Grading and POM gain identity-specific readouts; Puckering records its unsolved native physics rather than presenting imaginary stiffness. Avatar selection no longer masquerades as a pattern. Scene pattern selection opens an actual pattern edit; line selection opens measured boundaries; selecting blank Rust 2D/3D canvas clears the stale object context.
3. **Specific editable controls.** Pattern: Name, Grainline Angle (deg), Seam Allowance (cm), Cut Quantity, Layer Index, 3D visibility, Lock, Assigned Fabric. Fabric asset: Name, Base Color, GSM, thickness (display mm, stored m), approximate Warp/Weft Stretch, Bend, Damping, Friction, Roughness, Metalness, Sheen. Button instance: diameter, holes, 2D X/Y and color. Buttonhole instance: length, width, rotation, 2D X/Y, thread color. Topstitch instance: actual stitch length (mm) and derived SPI, offset, multiple lines, line distance and color. Graphic: dimensions, position, rotation, opacity and name. The underlying EXO project already uses these keys; all editing applies to real annotation/material values, not static display mocks.
4. **Native material, pattern and lines.** Real Rust `s.template.panels`, `s.template.fabrics`, `s.panels[].boundaries`, `s.uv`, `s.positions` produce per-pattern area/perimeter context, named line 2D/3D live lengths, stretch, assigned native fabric, material thickness and grainline, mesh vertex/triangle counts, position and rotation. A selected line's drafting target remains a separate stored specification with revision guard, not an elastic constraint. Measured values are displayed without fabricating a 3D draft value when mapping is missing.
5. **First-class native sewing inspection.** Native sewing relationships are listed in the Property Editor when the Sewing workspace is selected. Selecting a pair resolves Rust template seam refs and their **individual subrange lengths** (interpolated along rest UV arclength and live cloth positions), reverse orientation, ease permission, native seam stiffness and measured 3D seam gap. CLO sewing tension/turn/fold are not misrepresented as existing Rust material forces.
6. **Display-only units** under the Property Editor: cm, mm and in. Conversion is reversible and changes no project or Rust geometry. A native target specification entered in another unit converts back to centimeters before revision-guarded native save. View-only units do not claim to override global CLO user preferences.
7. **Physical support boundaries.** Enabled controls only mutate existing draft document fields or existing native line-spec. Rust has a real Fabric Library with editable warp/weft, shear, bend, mass, thickness via distinct native editor, but these are not falsely presented as CLO-fabric lab coefficients. No physical elastic-on-segment, seam taping width/preset/extension, sewing tension/fold, Bond/Skive or Solidify constraints are implemented in Rust yet; their UI remains unavailable with reason. Visual stitch/button annotations are not garment fastener mechanics.

## Required additional physical work, ordered by dependency

**Phase 1 — exact installed-app audit:** Enable Accessibility and Screen Recording for the automation host, or capture CLO 7.0.242 screens manually. Open a disposable CLO project without modifying user garments. Record each selectable object/tool/context, every expanded Property Editor group, hidden/disabled conditions, fields/units/defaults/tooltips and screenshots. Diff with this matrix. No claimed pixel parity until completed.

**Phase 2 — typed authoritative selection state:** A native-and-draft selection discriminated union with `kind`, `documentId`, `stableId`, `revision`, `origin`, `subrange`, multi-selection and explicit stale-reset. Extend native internal lines, sewing pairs, sewing style, seam tape, topstitch style, hardware style, avatar/arrangement points and renderer/window settings. Selection must be the sole source of the right editor schema. Keep native vs EXO draft IDs/units separate.

**Phase 3 — property registry and native command contracts:** Each control declares selection kind, name, unit dimension, target document, ranges, required capability, physical or purely optical effect, transaction/undo and disabled reason. Every edit validated on agent API and Rust bridge with expected revision, no stale writes. Read-only fields derive from native geometry and retain null/unavailable semantics. Add calculator and user-selected global display unit policy.

**Phase 4 — solver parity:** Implement anisotropic elastic line target/rest length and strength, tape edge reinforcement with width/material/extension and collision response, sewing tension/ratio and fold/turned constraints. Then implement Bond compositing, Skive local softening and Solidify preserving saved fold/drape. Each action must materially change the appropriate constraint and produce a repeatable measurable cloth response; do not unlock a cosmetic-only checkbox.

**Phase 5 — assets and advanced property contexts:** Shared vs instance topstitch styles (SPI, spacing, thickness Tex/Tkt/Nm/Den/mm, face, line count, multiple layers), physically modeled button/buttonhole/hardware, fabric lab-presets and separate PBR appearance, graphics UV, binding, grading POM, arrangement volumes, avatar materials and mesh settings. Import/export and undo preserve relationships and references.

**Phase 6 — regression and visual parity:** For each selection type capture screenshot pairs in native CLO 7.0.242 and EXO V2 at the same dimensions and tool state, compare field labels, section order, expansion, keyboard navigation, units, disabled states and results. Log unsupported controls and numerical tolerance differences. Only after all gates pass may full property-editor parity be claimed.
