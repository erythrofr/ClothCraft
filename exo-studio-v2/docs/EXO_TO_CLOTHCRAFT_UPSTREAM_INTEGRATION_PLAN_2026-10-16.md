# EXO V2 → ClothCraft integration plan

**Prepared:** 2026-10-16. **Current EXO repository:** `https://github.com/mikristian/exo-sample-3d`; feature branch `feature/studio-v2-clo-visuals`. **Independent ClothCraft upstream:** `https://github.com/erythrofr/ClothCraft`, observed checkout baseline `20b4db9`. This document is a migration plan. It does not assert any upstream branch or pull request has been published.

## Ownership and boundaries

EXO and ClothCraft serve different surfaces. The user-facing EXO V2 React studio, 400 textile reference presets, 2D/3D layout and community UI are EXO product features. ClothCraft's Rust code is the physics/garment/authoring backend with project schemas and reproducible numeric tests. Do not move EXO UI, marketplace code, screenshots, prebuilt applications, branded garments or downloaded textures into the ClothCraft Rust repository merely because EXO uses that engine.

The integrated EXO bridge lives at `integrations/clothcraft/exo-session.rs` and the local ClothCraft checkout contains an **untracked** `src/bin/exo-session.rs`. Treat the untracked file as local user work: copy only reviewed, general-purpose portions to an isolated fork branch after comparing it with the upstream authoring APIs. Do not reset, clean or overwrite the upstream checkout. Upstream repo `AGENTS.md`, `AI_START_HERE.md`, `README.md`, `ROADMAP.md`, `docs/handoff.md`, `docs/architecture.md`, `docs/authoring.md` and `docs/ogc.md` govern any implementation in that checkout.

## Publishing and verification sequence

1. Publish the complete reviewed EXO change snapshot on `feature/studio-v2-clo-visuals` of `mikristian/exo-sample-3d`, verify the remote commit, and keep `main` untouched pending review. EXO CI: `npm run build`, `npm run check:materials`, `npm run check:clo7-fabrics`, `npm run check:fabric-scans`, `node --test integrations/clo-connect-licensed/library.test.mjs`; add dedicated native UI QA as available.
2. Compare `git diff origin/main` in the local ClothCraft checkout after creating an integration branch from the exact upstream baseline. Save any local untracked files before changing branches. Do not merge EXO repo history wholesale into the separate upstream Rust repository.
3. For each phase above, make one small isolated commit (or a short reviewable series) in a fork of `erythrofr/ClothCraft`, including upstream-native unit tests, a technical rationale, documentation and truthful limitations.
4. Run CPU-first upstream checks (`cargo build --locked -j 2`, `cargo test --locked -j 2` and any relevant scripts in upstream `AGENTS.md`). Additional GPU work requires a separately agreed local run. Run EXO integration smoke and save/reload tests against the proposed upstream build in a sandbox.
5. Open independent pull requests against the ClothCraft repository only after each phase is reviewed. Include a before/after command example and test results. Wait for upstream review/approval; a fork push or PR is not an upstream merge.
6. Once upstream changes are accepted, update EXO's pinned ClothCraft source revision, adapt the bridge if the public API changed, rerun EXO regression checks, and merge EXO's feature branch through its own review process.

## Release gates and unresolved choices

- **Rights:** Poly Haven/ambientCG source maps recorded as CC0 may live in EXO if provenance/hashes pass. Downloaded CLO-SET CONNECT materials with unknown or restricted licenses stay in local intake, excluded from Git. Native CLO program resources and private user garments never go to the ClothCraft fork without explicit rights review.
- **API compatibility:** Upstream `ReferenceSolver::step`, project v1, garment templates v1/v2, fitting project v1 and material coordinates are stability constraints. Explicit schema migration is required if any serialized field changes.
- **Scope:** Keep shop/community features, native macOS signing and CLO7 visual matching out of the upstream solver patch series. P1–P4 can be proposed as engine/editor extensions where justified; P5 should proceed only with numerical evidence.
- **Decision point:** Choose upstream contribution route (personal fork and PR versus private downstream fork) after the EXO GitHub snapshot has been verified. Avoid force pushes to upstream or rewriting public history.
