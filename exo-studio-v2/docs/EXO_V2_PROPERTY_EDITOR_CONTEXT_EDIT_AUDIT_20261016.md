## Pattern and other contexts

The deep reference audit establishes that CLO's editor follows the **selected object kind** (whole pattern, edge, internal line/shape, sewing line, fabric, topstitch, graphics, hardware, avatar), and a blank selection can leave the editor body empty. The live captures for this run **do not show a selected pattern**. The following is the current EXO source implementation, **not observed CLO pattern row order**:

- `CloObjectPropertyFields.jsx` exposes draft pattern **Name** (`information`), **Layer / Show in 3D / Lock Pattern** (`simulation`), **Assigned Fabric** (`fabric`), **Grainline Angle / Seam Allowance / Cut Quantity** (`arrange`). No editable draft pattern `itemNo` is in the reviewed `GROUP_FIELDS.pattern` mapping. Native pattern perimeter, thickness and other live measurements in the accordion are readouts; do not treat them as editable.
- A selected native Rust edge exposes measured 2D/3D length and stretch, plus **Target 2D length** if a Rust setter exists; elastic and seam-taping inputs are disabled because force/tape simulation is unsupported. Draft edges may only have 2D measures. Pattern perimeter must stay separate from edge arclength.
- The `CONTEXT_GROUPS` dispatch explicitly distinguishes fabric, sewing, button, buttonhole, topstitch, graphic, avatar, grading, POM, puckering, with other group mappings for project/pattern/line. Some contexts contain explanatory readouts rather than independently editable native properties; selected type and active tool alone must not be conflated.
- `CloPropertyEditorAccordion.jsx` chooses `objectSelection` before native line/sewing/pattern, with project fallback and group-specific disclosure state. The parent must clear stale selections after object changes and keep the selected Object Browser row, inspector heading, group content and underlying edit target in sync. The project fallback currently makes an empty-state parity review necessary.

## Edit / dropdown contract and known gaps

For supported **draft** values, `EditorInput` resolves the target with `resolveCloDraftTarget`, looks up `CLO_DRAFT_FIELDS[kind][field]`, and submits edits through `onEdit(selection, field, converted)`. Numeric values can have display conversion factors; text/number entries submit on blur or Enter; boolean, fabric select and color picker submit on change. Validation failures display an inline `role="alert"` error. The Assigned Fabric dropdown is populated from `project.fabrics`, not from an external CLO preset list. All displayed rows depend on a valid draft target and schema field, so a listed mapping alone does **not** guarantee an editable control for every selection.

Accordion headings are buttons with `aria-expanded`, `aria-controls`, and conditionally hidden regions. Fabric `Material` and `Physical Property` are genuine EXO section groups. The CLO subgroups **Construction**, **Basic Parameters** and **Reflection** have not been implemented as verified independent nested disclosures in the reviewed material overview. There is a length-display unit selector in EXO; verify actual changes to numeric measurements and edit conversion without accidental magnitude changes. Native Rust fabric editing lives in a separate Fabric workspace; changes to EXO's draft material appearance or physical estimates must not be labeled native physics calibration.

High-priority missing or not-yet-proven functionality: per-object edit persistence across selection and reload; selected-pattern Item No.; contextual blank-state clearing; CLO-like nested disclosure behavior; fabric Open/Save semantics; Texture Mapping and material type selection; map assignment and alpha effects; opacity editing; face-specific materials; complete measured Physical Property schema and solver coupling; native pattern/edge/sewing commands for every exposed editable control. Some are intentionally disabled and should remain so until functional.

## Practical QA acceptance checklist

1. **Fabric selection:** create two distinctly named EXO draft fabrics, select each through Object Browser, assert header and group order `Information → Material → Physical Property → Miscellaneous`, with Information suborder `Name → Item No. → Construction → Supplier → Owner`. Select away and back; assert no value leaks across fabrics.
2. **Real draft edit:** change Name, Item No., Construction, Supplier, Owner and Color individually; verify persisted state, related display surfaces and reload. Edit invalid constrained numeric values to test visible validation and preservation of prior valid value. Check undo/redo if provided by the parent command layer.
3. **Dropdown interaction:** select Assigned Fabric on a pattern; verify it changes that pattern's material ID and updates its view. Open/close accordion sections with pointer and keyboard, check state, label, focus, and nested subgroup behavior only after those controls actually exist.
4. **Context switching:** select pattern, edge, fabric, sewing and nothing; check matching groups and values; previous selected-item fields must disappear. Pattern body must not silently reuse fabric fields. Verify project fallback only if intentionally selected as project settings.
5. **Read-only versus editable:** fabric front/back/side displays Front active while unsupported faces stay disabled; display-only Texture Mapping, map readouts, opacity and synthetic `Fabric_Matte` label never suggest that user edits are persisted. Supported appearance edits visibly update previews; Physical draft values are clearly identified as approximations.
6. **Native boundary and reload:** confirm that draft edit callbacks do not silently mutate a different native Rust fabric; verify native material changes through the actual Fabric workspace and subsequent editor refresh. Test saved native project reopen without losing existing assets.
7. **CLO reference coverage:** in a disposable CLO 7.0.242 project, open Construction, Material Type, Texture Mapping, Front/Back/Side and Reflection; scroll through Physical Property; capture labels, control type, options, units and edit/undo effects. Repeat for selected whole pattern and edge. Until then, mark exact CLO editability and ordering beyond the photographed rows as unknown.

**Implementation note:** This document alone changes no UI, native application, materials or projects. Direct source observations can become stale while parallel workers edit EXO; rerun the acceptance checklist against the integrated signed native app before assigning parity status.

## Integrated update and signed native V2 verification

This section supersedes the **implementation-gap statements** above where the implementation subsequently changed; the captured CLO observations and remaining capability limitations remain unchanged.

- **Native editable Information:** Pattern and Fabric Name now edit the authoritative Rust template through revision-validated `set-property` operations. Pattern/Fabric Item No. values persist in a project-bound atomic sidecar. Fabric Construction, Supplier and Owner are independently editable metadata fields with validation and restart persistence. Type remains a read-only object-classification row. Draft patterns also support independent Item No. through the existing undoable EXO draft transaction.
- **Context isolation:** Native Object Browser now lists actual Rust panels/fabrics, not unrelated EXO draft rows. Pattern, Fabric, selected line, and no-selection contexts switch their visible accordions according to selected object. In Fabric, the Information section no longer retains old selected-pattern perimeter/boundary readouts. Native Fabric's Material and Physical Property groups show the Rust-backed material controls in the correct Property Editor context.
- **Limits:** Independent Front/Back/Side materials, arbitrary CLO Material Type conversions, Fabric PBR map imports, real Bond/Skive/Solidify, sewing-tension and elastic solver knobs remain unsupported; disabled/read-only presentation is intentional. PBR Textures/Reflection and exact CLO dropdown options are not claimed at parity.
- **Validated:** `node integrations/clothcraft/check-v2-property-persistence.mjs` (including saved restart, stale revision and bad-target rejection), `node integrations/clothcraft/check-v2-property-commands.mjs` (draft edit bounds and undo), `node integrations/clothcraft/qa-v2-property-context-extended.mjs`, `node integrations/clothcraft/qa-v2-native-property-editor-20261016.mjs` (native browser selection + edit Pattern→Fabric→Pattern; correct physics controls), and `node scripts/qa-installed-v2-property-readonly.mjs` all passed. The signed app's served UI bundle, packaged bridge service and native Rust executable were confirmed byte-for-byte equal to current source. All live-app tests were read-only; editing QA used an isolated disposable garment project. No separate browser window was opened, and the live saved garment was not altered.
