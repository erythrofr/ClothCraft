## Features in V2

1. Original EXO Sample 3D menus, sidebars, left double toolbars, object browser, right property editor and bottom simulation bar remain around ClothCraft's linked Rust-backed 3D and 2D editor.
2. V2 Three.js viewer ports the **actual original EXO GarmentViewport DCC XYZ + free rotation ring mechanics**, including visible RGB 360° rings and centrally located translation gizmo, with selected-panel hover highlighting. Bounding boxes are optional and **off by default**. Direct Move 3D drags the selected cloth mesh away from the avatar in real time; its color-coded sewn edges, connecting guide lines, and section-marker dots follow the visible moving cloth while the rest of the simulated garment stays in place. The viewport also reuses the original Garment Studio's pale circular floor, directional/hemisphere/rim lighting, sparse grid and vertical center axis, plus Front/Right/Top/Orbit controls.
3. Before simulation, Direct Move commits upstream ClothCraft's authored `Place` edit. After simulation, the new native Rust `pose-panel` instead **rigidly repositions the current draped vertices and preserves their folds**, changing **only** the selected panel's live solver state; every other sewn panel is kept at exactly the same coordinates and the current simulation time is preserved. Sewing constraints remain defined and resolve on the next physics step, rather than physically stretching the neighboring cloth continuously during the pointer gesture. A separate Grab/Stretch action invokes new experimental Rust `pull-panel`, applying a bounded 3D Gaussian brush to one panel's simulated vertices while leaving other panel coordinates exactly unchanged. Both native motion operations discard stale contact caches prior to the next physics step.
4. **Spread panels** explicitly invokes Rust reset, returning *all* panels to the authored off-body initial pose and resetting simulation time. This is deliberately **not** Undo for physics frames. Undo/Redo handles authored pattern edits only.
5. V2 2D view aligns the front pattern over the **dark central drafting axis**, with the silhouette of the **currently visible native Rust 3D avatar mesh** centered on the same axis. `avatarSilhouetteFromMesh.js` projects the current `snapshot.avatar.positions` and `snapshot.avatar.triangles` orthographically, traces the filled contour and negative-space openings into a simplified SVG path, and preserves that mesh's proportions. It replaces both the hardcoded Garment Studio `FlatAvatarSilhouette` and the earlier single fixed CC0 mannequin SVG. The actual 3D avatar and silhouette now share one geometry source: hide the avatar in 3D and the 2D silhouette disappears; on a new native garment/avatar load the 3D mesh and silhouette refresh together. If no 3D avatar is loaded, the 2D board displays no body. SVG height is normalised to a 1.75 m **drafting reference only**, not measured girths, a body scan, or a substitute for collision geometry. All native UV, sewing indices, original panel dimensions and editable coordinates remain unchanged. The original-inspired grayscale 50 mm and 25 cm grids, panel dimensions, proportional guide lines, seam dots, FRONT/GRID widget, Frame all / Focus selected / Center axis and cursor zoom remain functional.
6. **Exact original Garment Studio environment port:** the 3D renderer imports our original `GarmentViewport.jsx` neutral daylight gradient (`#919298` → `#d4d5d9` → `#f2f2f7`), PMREM `RoomEnvironment`, sRGB/ACES Filmic exposure 1.1, shadow-map lighting with studio/softbox/dramatic/neutral presets, pale circular `#ebebed` floor and `GridHelper(5.5,22)` with centered floor/world axes. The compact upper-right XYZ/F/R/T/3D mini-widget is present on the 3D viewport, while the original-style FRONT/GRID/Frame/Focus controls are in the top-left corner of the 2D board. ClothCraft's Rust garment meshes and physics have not been replaced.
7. The 2D drafting canvas and grid use the **original Garment Studio** neutral gray `#c6c7c9`, with the exact solid original pattern fill `#f4f4f3` at **opacity 1** for both selected and unselected panels. The silhouette is not visible through the shirt. Selected panels remain distinguishable by original edge, points and handle highlights rather than becoming semitransparent or changing to yellow fabric. The mesh-projected SVG is generated locally from the currently displayed 3D body's own geometry, **not from copied proprietary CLO3D vectors or assets**. A different native avatar mesh yields a different 2D outline. Selecting an avatar in EXO's *separate* project editor does not, by itself, switch the ClothCraft Rust collider; that is a separate interoperability task.
8. UI cleanup moves Rust status, Sim/Pause and single-step control to the original EXO **top menubar**, next to global Undo/Redo/Save/Export. Redundant ClothCraft title bars over both viewports and the extra rust-explanatory heading were removed; the bottom tool rail and concise simulation diagnostic bar remain. The original EXO outer chrome uses its exact charcoal `#252527` menu and neutral `#2d2d2e` side panels rather than invented blue gradients.
9. **Right toolbar three-dot menu relocated:** the existing `MoreHorizontal` All/Focused tool-switch is now inside the original two-column RightToolPalette, immediately before the Scene hierarchy tool. The old separate header button is removed. Every focused workspace still exposes the menu and its exact prior behavior. There is still only one logical All/Focused control.
10. Rust-backed 3D sewn-section markers are **bright, unlit, non-depth-occluded colored spheres** at real `snapshot.seams[].guides` endpoints, with correspondence guide lines and toggleable visibility. They use seam-specific colors and are distinct from the floor's room lighting; no decorative/random sewing marks are invented.

## How to save more milestones

Use Git commits as frequent checkpoints, a **branch per feature experiment**, and an annotated tag or GitHub release for each stable, tested build. For example, leave V1 tagged and branch V3 from the last verified V2 commit rather than overwriting the only working copy. Push only after reviewing ignored/private assets, remote auth and desired repository visibility. Store garment JSON, simulation states and private/high-resolution avatars in separately versioned, dated backups, not merely in source Git. Git LFS may be useful for approved non-private binary assets but does not replace offline archival backups or solve redistribution rights.

The local V1 tag and V2 branch are **not themselves remote GitHub backups** until explicitly pushed. Verify a remote push, GitHub release and checksum of backed-up data before assuming a second machine can recover the entire garment and app state.

## Recover an off-body pattern arrangement for another simulation

The original EXO top menubar (Rust hybrid mode) has a dedicated **RESET PANELS** action next to SIM and STEP. This is separate from Undo. It stops a currently running simulation, clears an in-progress fabric grab, waits for pending Rust operations, refreshes the native revision, and calls the existing Rust `reset` operation to restore `garment.initial_state` at time zero. The 2D pattern shapes, sewing connections, materials and garment template stay unchanged; the 3D cloth moves back to its authored off-body assembly positions for another simulation. The existing **Spread panels**, bottom **RESET** and standalone Fit reset actions call the same recovery workflow.

`node integrations/clothcraft/qa-v2-reset-panels.mjs` uses dedicated, disposable QA services on ports 5415/5416 (not the installed apps). It establishes an authoritative off-body baseline (because a saved project may reopen in a draped state), then verifies `RESET PANELS` after a solver step and **while running**. Both resets must restore exact baseline coordinates, time 0, identical pattern/template data and remain paused until the next explicit SIM click. This does **not** undo historical 2D drafting edits or reset pattern dimensions.

### Recovery if the saved drape itself prevents loading

A corrupt or physically intersecting saved simulation state can make ClothCraft's native `open` fail before any 3D pattern is visible. **RESET PANELS remains enabled even then.** The backend's explicit `recover-off-body` request copies both `fitting-project.json` and `fitting-project.json.native` to timestamped `*.before-off-body-reset-*.bak` files before rebuilding the native Rust session with the *same garment template, fabrics and seam links*, but fresh off-body solver positions (`state:null`, `mesh_signature:null`). It saves the recovered state only after a successful native Open. This recovery never happens silently during app launch; clicking Reset explicitly authorizes it. A failed recovery leaves the pre-recovery backup and original saved project intact. `node integrations/clothcraft/qa-v2-reset-recovery.mjs` tests this behavior using an isolated copy of the current saved fitting project and simulated native-load error, confirming both backups, a restored 2D/3D workspace and identical authored pattern data, without modifying live user files.
