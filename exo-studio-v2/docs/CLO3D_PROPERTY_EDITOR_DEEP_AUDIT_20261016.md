# CLO Property Editor deep audit and EXO V2 parity specification

**Date:** 2026-10-16. **Deliverable:** official-reference inventory, local evidence boundaries, EXO V2 mapping, priority and acceptance criteria. **Scope:** right-side selection-sensitive Property Editor, including linked Object Browser property contexts. This is a design and source audit; it is not a claim that the installed CLO application's rendered UI was visually captured.

## Evidence, version boundaries, and how to read this audit

- **O** means the control or behavior appears in an official CLO Help Center article. The linked pages are living documents and can describe newer releases than **CLO 7.0.242**. Therefore **O does not automatically mean verified in 7.0.242**.
- **L?** means exact label, order, defaults, ranges, visibility, and behavior must be checked in the *locally running* CLO 7.0.242 Property Editor. No screenshots or interaction with that application were available during this worker audit. Existing project audit records identify `/Applications/CLO_Standalone_OnlineAuth.app`, but a bundle's presence is not evidence of an active 7.0.242 session.
- **E** means directly supported by the current EXO V2 source examined on October 16, particularly `src/components/CloPropertyEditorAccordion.jsx`. **E-partial** means UI or data exists without verified matching physical semantics; **E-no** means no matching editor/solver binding was established in that inspected code. Other project work may be landing concurrently; verify after integration.
- **P** means proposed future EXO behavior. **Do not present P or L? as an observed CLO screenshot fact.**

Primary official reference: [Property Editor](https://support.clo3d.com/hc/en-us/articles/115004877468-Property-Editor). This confirms that the editor changes according to selected pattern, internal shape, sewing, stitch, sewing style, fabric, button, buttonhole and avatar, with simulation/wind/2D-window properties invoked via background context menus. Numeric fields support right-click Calculator and Convert, and items can carry an Item No. The specific properties below must be dispatched by **selection object kind**, not merely the active toolbar tab.

**Important version caution:** The Help Center includes older article families and pages updated in 2025–2026. For example [Select Binding](https://support.clo3d.com/hc/en-us/articles/360000628128-Select-Binding) explicitly calls out a *Both (ver 7.0)* placement option, while newer seam-tape articles refer to 2024.2 migration. Record the local build and screenshot before calling an individual feature “exact CLO 7.0.242 parity.”

## Current EXO V2 code facts (read-only October 16 snapshot)

The editor at `src/components/CloPropertyEditorAccordion.jsx` exports eight IDs: `information`, `selected-line`, `simulation`, `fabric`, `bond`, `solidify`, `arrange`, and `miscellaneous`. A compact Property Editor remains docked below the Object Browser, with expandable sections. It distinguishes a Rust `selection.kind === 'line'` from `pattern`, draft line selection, some Object Browser kinds, and project fallback, but **does not yet have dedicated property forms for every CLO object kind**.

On a selected Rust line the editor displays **2D Line Length**, **3D Line Length**, **3D Stretch**, sewing-link IDs, and an editable **Target 2D length (cm)** specification (0.01–1000 cm, only with a Rust source and setter). Source text correctly states that a target length specification is *not* an elastic force. Draft-only selection can provide a 2D length while leaving 3D length unavailable. For Rust patterns, measured 2D/3D perimeters are displayed. Elastic and Seam Taping have disabled controls and explanatory readouts; Bond and Solidify are explicitly unconfigured. The simulation panel can issue simulate/pause/reset callbacks. Fabric panel displays assigned fabric and, in draft mode, swatch/GSM. Arrangement can report position X/Y/Z or draft staging offsets, but these do not establish CLO arrangement-point semantics. The rendering of children under the active workspace and the pattern-properties portal should remain intact during future upgrades.

**EXO evidence pointers:** `CloPropertyEditorAccordion.jsx:8-27` group mapping; `:38-50` selection/type resolution; `:85-110` measured line and unavailable forces; `:113-160` simulation, fabric, Bond, Solidify, staging and portal; `:166-185` accordion shell. See also `docs/CLO3D_PROPERTY_EDITOR_AUDIT_20261016.md` and `docs/EXO_V2_RIGHT_PROPERTY_EDITOR_20261016.md`. These documents reflect earlier checkpoints; when they disagree about V2 measured-line support, **the current source governs**.

## Field notation

In each matrix, `R` = read-only computed/display, `N` = number, `B` = boolean, `S` = dropdown/enum, `T` = text, `C` = color/material picker, `A` = action. A range/default marked **?** is not confirmed by the cited source and requires a 7.0.242 capture. Length defaults follow project unit settings (mm/cm/in) when applicable; do not hardwire centimeters as CLO's universal display unit. `--` is unknown/unavailable, **not zero**.

## Conditional behavior and exactness rules

1. **Selection drives schema.** `pattern`, `outerEdge`, `internalLine`, `internalShape`, `sewingPair`, `seamTape`, `topstitchStyle`, `topstitchInstance`, `binding`, `fabricAsset`, `graphic`, `button`, `buttonhole`, `avatar`, `gradedPiece`, `POM`, `arrangementPoint`, `simulationSettings`, `windSettings`, `window2D`, or `none`. The current generalized eight-group accordion can stay as shell, but only context-valid sections may appear. No stale pattern name/measurement after deselection.
2. **Every numeric field declares dimensionality:** length (mm/cm/in), area, ratio %, angle degrees, SPI, thread thickness unit (Tex/Tkt/Nm/Den/mm), per-area mass (GSM), or dimensionless scalar. UI conversions never rewrite physical meaning. Null/unmapped values are `Unavailable`.
3. **Do not invent defaults.** Documented values are Elastic Strength 10, Elastic Ratio 100%, and ratio range 0–200%; Skive 1–100%; topstitch max five layers; Binding Width 1–50 mm, Length 50–200%, Particle Distance 4–20 mm as described in the linked current binding article; Fold Angle 0–360°. The remainder are L? until version-specific capture.
4. **CLO instance versus asset:** a Topstitch or Fabric style entry has shared specifications; its instance on a garment has spatial placement/assignment. Editing the selected garment line must not silently change the shared global style.
5. **Conditional disabling:** topstitch Flip inactive on pattern cutting lines; stitch-line distance only for multiple lines; stitch OBJ optimization only in OBJ mode; binding Extend must have valid surrounding geometry; sewing Fold fields depend on Turned state; pattern arrangement-point fields require an arrangement point; native physics toggles require a solver-capability response.
6. **Transactions:** mutation includes selected object ID, revision and validated units, and must reject stale updates or missing geometry. Document model update, render update, undo/redo and saved reload must agree.
7. **Multi-select:** heterogeneous contexts show common compatible fields and mixed values; homogeneous edges may expose Total Length. Never silently choose the first target.
8. **Version comparability:** capture CLO 7.0.242 (exact About dialog/build) with selected pattern, outer edge, internal line/shape, sewing line, taped segment, topstitch asset/instance, Fabric asset, graphic, button/hole, avatar, graded piece, POM, Bond/Skive, arrangement point, and blank 2D/3D canvas. Capture expanded accordions, units, tool, disabled states, tooltip, and one benign field change per context. Record screenshot names and observations in a follow-on evidence appendix.
